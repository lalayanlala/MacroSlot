# MacroSlot

FFXIV Patch 7.57 / Dalamud API 15 向けの小型プラグインです。`/mslot` で、指定したホットバーの指定した1スロットだけを、既存の個人マクロまたは共通マクロに置き換えます。他のスロットは変更しません。

## コマンド

```text
/mslot personal <マクロ番号> <ホットバー番号> <スロット番号>
/mslot shared   <マクロ番号> <ホットバー番号> <スロット番号>
```

例:

```text
/mslot personal 50 1 5
/mslot shared 50 1 5
```

どちらも「ホットバー1の5番スロット」を変更します。前者は個人マクロ50、後者は共通マクロ50を設定します。

- マクロ番号: `0`～`99`（ゲーム内部の番号。マクロ一覧の番号と同じ）
- 通常ホットバー: `1`～`10`、スロット `1`～`12`
- クロスホットバー: `11`～`18`、スロット `1`～`16`

## 仕組みと安全策

`FFXIVClientStructs` の `RaptureHotbarModule.SetAndSaveSlot` を使用します。このゲーム関数は指定された1スロットを現在有効なホットバーグループへ書き込み、保存を要求します。バー全体のコピーや再構築はしないため、指定外のスロットは維持されます。

ゲーム関数自体には十分な範囲チェックがないため、本プラグインは呼び出し前に全引数を検証します。また、ログイン状態、ホットバーモジュールの準備完了、ホットバーデータの読込成功を確認します。意図しないPvP用設定の変更を避けるため、PvPホットバーが有効な間は処理を拒否します。ゲームメモリへ直接値を書き込まず、クライアントが提供する設定・保存関数だけを呼びます。

共通マクロは、ホットバー内のマクロIDに共通ページを示すbit 8（`0x100`）を付けて指定します。

## 必要環境

- Windows版 FFXIV Patch 7.57
- XIVLauncher / Dalamud API 15
- .NET 10 SDK
- XIVLauncherでゲームを一度起動し、API 15の開発用Dalamudファイルが `%APPDATA%\XIVLauncher\addon\Hooks\dev` に存在すること

Dalamud API 15はPatch 7.5系向けで、公式SDKは `Dalamud.NET.Sdk/15.0.0`、ターゲットランタイムは.NET 10です。本プロジェクトはそのSDKを使用します。

## ビルド

ソースディレクトリでPowerShellを開き、次を実行します。

```powershell
dotnet restore
dotnet build -c Release
```

成果物は通常、次の場所に生成されます。

```text
bin\Release\MacroSlot\MacroSlot.dll
bin\Release\MacroSlot\latest.zip
```

SDKの細かな出力構成により、`latest.zip` が `bin\Release` 直下に置かれる場合もあります。

## 開発プラグインとして読み込む

1. ゲーム内で `/xldev` を開きます。
2. Dalamudの開発プラグイン設定で、ビルドされた `MacroSlot.dll` またはその配置フォルダを開発プラグインの場所として追加します。
3. プラグインを読み込みます。
4. `/xlhelp` に `/mslot` が表示されることを確認します。

## ゲーム内検証の留意点

最初は重要でない空スロットと、内容が分かりやすいテスト用マクロで確認してください。

1. PvPエリア外で、ホットバー1の5番以外に識別しやすいアクションを置きます。
2. 個人マクロ50に、害のない内容（例: `/echo personal test`）と分かりやすい名前・アイコンを設定します。
3. `/mslot personal 50 1 5` を実行します。
4. 5番だけが個人マクロ50になり、同じバーの他スロットが変化していないことを確認します。
5. 共通マクロ50も別の名前・アイコン・`/echo shared test`で用意し、`/mslot shared 50 1 5` を実行して切り替わることを確認します。
6. ジョブを変更し、対象ホットバーが共有設定かジョブ別設定かに応じて保存先が期待どおりか確認します。
7. 一度タイトル画面へ戻る、または通常終了・再ログインし、変更が保存されているか確認します。

注意:

- `personal` / `shared` は「参照するマクロの種類」です。ホットバー自体の共有・ジョブ別設定はゲーム側の現在設定に従います。
- マクロ内容が空でもスロット設定は可能です。実行前に対象マクロの中身を確認してください。
- 戦闘中やコンテンツ中ではなく、安全な場所で初回検証してください。
- パッチでクライアント構造やシグネチャが変わる可能性があります。7.57以外では、そのパッチ対応版のDalamud/FFXIVClientStructsで再ビルド・再検証してください。
- プラグイン使用は自己責任です。XIVLauncher/DalamudおよびFFXIVの利用条件・コミュニティルールを確認してください。

## 実装上の前提

- `/mslot` のコマンドハンドラから、`IFramework.RunOnFrameworkThread` でゲームのフレームワークスレッドへ処理を移します。
- ユーザー入力は1始まり、ネイティブAPIへ渡すときだけ0始まりへ変換します。
- `SetAndSaveSlot` の `allowSaveToPvP` は `false` に固定しています。
- API 15より後の破壊的変更には追従作業が必要です。
